고객의 수화기에는 침묵 대신 이 문장이 나갑니다: 🔊 "연결 상태가 좋지 않아 상담원을 연결해 드리겠습니다."

재생을 누르면 8 kHz 위반 오디오가 fail_fast 파이프라인에 들어갑니다.
정책은 예외를 없애지 않습니다 — 예외의 관객을 바꿉니다. fail_fast는 개발자에게 크게 들리도록, handoff는 고객에게 들리지 않도록. 어느 쪽이든 위반 자체는 같은 게이트가 같은 지점에서 잡았고(경계의 일), 무엇을 할지는 정책의 일입니다. handoff의 FALLBACK 흔적은 운영에서 "오늘 폴백이 몇 건이었는가"를 세는 근거가 됩니다 — 조용히 넘어간 장애는 셀 수 없습니다.
오케스트레이터 run()의 except 블록 하나가 갈림길 전부입니다: 
except ContractError:
    if self.policy == "fail_fast":
        raise                      # 개발: 그대로 위로 — 크게, 원점에서
    # 운영: 무너지는 대신 상담원 연결로 강등 — 장애가 침묵이 되지 않게 흔적을 남깁니다
    res = {"intent": "unknown", "action": "HANDOFF", "slots": {},
           "say": "연결 상태가 좋지 않아 상담원을 연결해 드리겠습니다."}
    rec = self.tts.synth(res["say"])
    traces.append(("FALLBACK", 0.0))

주의할 점: handoff는 ContractError만 받습니다. 다른 예외(코드 버그)는 여기서도 그대로 터집니다 — 폴백은 "예상한 장애"의 통로이지, 모든 오류를 삼키는 담요가 아닙니다. 7-3의 bare xfail vs raises= 실험과 같은 원리입니다.

장애 처리고객 경험운영이 아는 것
아무 것도 안 함 (v0)침묵 또는 이상한 소리모름 — 항의 전화로 처음 인지
조용히 삼킴 (bare except)그럴듯한 오동작모름 — 지표가 오히려 깨끗해 보임
handoff + FALLBACK 흔적사과 문장 + 상담원폴백 건수·시각·원인 집계 가능

FALLBACK이 트레이스에 남으므로 운영 대시보드는 "왕복 p95"와 나란히 "폴백률"을 볼 수 있습니다. 폴백률이 튀는 날이 곧 재협상 테이블에 새 안건이 올라가는 날입니다.

§7의 통합 테스트에는 이 갈림길의 양쪽 끝이 각각 한 개씩 고정되어 있습니다: 
def test_contract_violation_fail_fast():
    with pytest.raises(PE.ContractError):
        make_pipe().run(AUDIO, 8000, "g01")          # 반드시 터져야 초록

def test_contract_violation_handoff():
    r = make_pipe(policy="handoff").run(AUDIO, 8000, "g01")
    assert r["nlu"]["action"] == "HANDOFF"           # 반드시 안 터져야 초록
    assert any(s == "FALLBACK" for s, _ in r["traces"])

같은 위반 입력(8000 Hz)에 대해 한 테스트는 "터짐"을, 다른 테스트는 "안 터짐 + 흔적"을 요구합니다. 둘 다 25 passed에 포함되므로, 나중에 누가 except 블록을 고치면 어느 쪽 약속이 깨졌는지 즉시 빨간불이 켜집니다 — 정책도 회귀 테스트의 보호를 받습니다.
