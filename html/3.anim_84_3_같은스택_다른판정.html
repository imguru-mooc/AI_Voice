분류 4유형 — MAU 조건은 어디에 왜 hold인가 — 저장소별 상이 확인일도 데이터다 block 우선 정렬의 이유
과정에서 확립한 분류 4유형: 무조건(Apache/MIT) · MAU 조건(SEED — 1천만 MAU 미만 무료) · 비상업 NC(EXAONE) · 저장소별 상이(Fish Audio). 오늘 manifest 5종에는 MAU 조건 항목이 없어 화면에 등장하지 않지만, 감사기는 mau_conditional 분기를 이미 갖고 있습니다 — 팀 manifest에 SEED가 들어오면 warn(임계 초과 전 재검토)으로 잡힙니다. 과제 2가 바로 그 실습입니다.
OpenAudio S1-mini는 GitHub v2.0.0과 PyPI v0.1.0의 라이선스 원문이 다릅니다(4주차 실측). 라이선스는 모델 카드가 아니라 설치 경로의 저장소 원문이 사양이므로, 어느 경로로 설치되는지 확정되기 전에는 pass도 block도 아닌 hold — 판정을 보류하고 사람을 부릅니다. 상업 전환에서만 hold로 승격되는 이유는, PoC에서는 이 불확실성이 경고로 충분하지만 상업에서는 계약 리스크이기 때문입니다.
manifest의 각 항목에는 checked: "2026-08-14"가 함께 적힙니다. 라이선스는 저장소가 바뀌면 함께 바뀝니다 — 유통기한이 있는 데이터입니다. 감사기는 확인일이 오늘과 다르면 "확인일 경과 — 재확인 권장"을 노트에 덧붙입니다. 규정 마감일(b14)과 같은 원리: 날짜도 데이터다.
감사 결과는 block → hold → warn → pass 순으로 정렬됩니다. 8-3 경보의 원칙과 같습니다 — 가장 큰 리스크가 맨 위에서 크게 말해야 합니다. 표 아래에 결정(g04)이 따라붙는 것은 7-5 g03 형식의 승계: 감사표는 상태를 말하고, 결정 기록은 행동을 말한다. 근거는 20자 이상 assert — 실측 111자로 통과했습니다.
