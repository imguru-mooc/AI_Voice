D31 FastAPI 음성 API 서버

요청과 응답의 일생, 업로드 한 건의 생김새, 상태 코드 고르기, 이벤트 루프가 막히는 순간, 번호표(Semaphore) 줄 세우기, WebSocket 메시지 흐름, 말 끝 찾기 손잡이를 직접 움직여 보는 수업 자료입니다. 탭 번호 D31-1 ~ D31-9는 노트북 · 워크시트 · 슬라이드의 🎬 번호와 같습니다. 숫자는 설명용 시뮬레이션입니다.

D31-1오늘 할 것: 노트북 함수를 API 서버로

단계를 눌러 할 일과 빈칸을 확인하고, 관련 애니메이션으로 이동하세요.

D31-2요청과 응답의 일생

엔드포인트를 고르고 ▶를 누르세요. 요청이 uvicorn → FastAPI(경로 찾기 · 검사) → 함수 → 응답으로 가는 동안, 오른쪽에 실제 요청 · 응답 글자가 채워집니다. '틀린 요청'을 켜면 어디서 멈추는지 보세요.

D31-3업로드 한 건 해부: multipart/form-data

파일을 고르면 클라이언트가 실제로 보내는 요청 본문 모양과, FastAPI의 UploadFile이 꺼내 주는 값이 나옵니다.

D31-4상태 코드 고르기

상황마다 서버가 돌려줄 상태 코드를 골라 보세요. 4xx는 '보낸 쪽 잘못', 5xx는 '서버 잘못'입니다.

D31-5이벤트 루프 한 명: 막힘 vs to_thread

모드를 고르고 ▶를 누르세요. STT 손님 3명과 /health 손님이 차례로 옵니다. 직원(이벤트 루프)이 직접 요리하면 모두가 기다리고, 주방(스레드)에 맡기면 /health는 바로 나갑니다.

D31-6번호표 줄 세우기: Semaphore(n)

번호표 수(n)와 동시 요청 수를 바꿔 보세요. n이 크면 줄 선 시간은 줄지만 GPU 메모리가 늘고, 한 번에 여러 개를 돌리면 한 건의 처리 시간도 길어집니다.

D31-7WebSocket 메시지 흐름 (/ws/voice)

▶를 누르면 연결 → 소리 조각 → 말 시작 · 끝 → final → answer → 답 소리 → audio_end 순서로 메시지가 오갑니다. 왼쪽은 클라이언트, 오른쪽은 서버입니다.

D31-8말 끝 찾기 손잡이: THRESH_DB · HANG_SEC

'진료 시간이, (쉼) 어떻게 되나요?'처럼 중간에 쉼이 있는 말입니다. 손잡이를 바꾸면 서버가 말을 몇 덩어리로 자르는지, 말 끝 → 글자가 얼마나 걸리는지 보세요.

D31-9정리 퀴즈: 이 상황에서 무엇을 쓸까?

음성 API 서버를 운영하며 만나는 상황입니다.
