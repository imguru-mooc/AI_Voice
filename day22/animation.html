D22 LLM API 연동

Claude · OpenAI · Gemini API의 요청 구조와 Streaming, 첫 토큰까지 시간(TTFT)과 비용, 음성 대화용 프롬프트 점검, 대화 이력(창 · 요약 · 끼어들기), API 키 안전을 직접 움직여 보는 수업 자료입니다. 탭 번호 D22-1 ~ D22-9는 노트북 · 워크시트 · 슬라이드의 🎬 번호와 같습니다.

D22-1오늘 할 것: 두뇌를 키우고 기억을 붙인다

단계를 눌러 할 일과 빈칸을 확인하고, 관련 애니메이션으로 이동하세요.

D22-2세 API의 요청 · 응답 비교

API를 고르면 같은 대화(시스템 지시 + 이전 1턴 + 이번 질문)를 그 API 형식으로 보낸 요청과, Streaming으로 돌아오는 이벤트 모양이 나옵니다. 다른 부분은 노란색입니다. 모델 이름은 2026년 10월 기준 예입니다.

D22-3Streaming 이벤트가 도착하는 모습

'요청 보내기'를 누르면 이벤트가 시간 순서대로 도착합니다. 네트워크 왕복 · 생각 시간 · 초당 토큰을 바꿔 TTFT와 전체 시간을 비교하세요. (설명용 숫자)

D22-4음성 비서 비용 계산기

한 턴의 입력 = 시스템 지시 + 이력 + 이번 말, 출력 = 답. 하루 대화 수와 단가를 바꿔 월 비용을 보세요. 단가는 100만 토큰당 달러(USD)이며 예시 값입니다.

D22-5음성용 답 점검기 (voice_lint)

아래 칸의 답을 직접 고쳐 보세요. 노트북의 voice_lint()와 같은 규칙(80자 · 2문장 · 마크다운 · 이모지 · 영어 단어)으로 바로 점검합니다. 소리로 읽을 때 어떻게 들릴지도 보여 줍니다.

D22-6이력 창 · 요약 시뮬레이터

'다음 턴'을 누르면 대화가 쌓입니다. 전략을 바꿔 매 턴 보내는 메시지와 입력 토큰, 그리고 마지막 '기억 질문'에 답할 수 있는지 보세요. 회색 줄은 이번 요청에 들어가지 않는 메시지입니다.

D22-7끼어들기와 이력 저장

비서가 답을 읽는 도중 사용자가 끼어든 시점을 바꿔 보세요. 답 전체를 저장하면 다음 턴에 LLM이 사용자가 듣지 못한 말을 들었다고 착각합니다.

D22-8생각 모드와 TTFT

생각(thinking · reasoning) 모드가 켜지면 모델은 답하기 전에 보이지 않는 생각 토큰을 먼저 만듭니다. 생각 토큰 수를 바꿔 첫 소리까지 시간과 비용을 보세요.

D22-9API 키 안전 점검

상황을 고르고 '안전 / 위험'을 먼저 판단한 뒤 판정을 보세요.
