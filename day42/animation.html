통화가 늘면 어디에 줄이 생기나

통화가 하나씩 늘어납니다. 소리는 api를 지나 asr · llm · tts를 차례로 거쳐 돌아옵니다. 통화가 많아지면 한 구간에 줄이 쌓이고, 오른쪽의 p95 지연이 목표선을 넘습니다.

코드 한 줄을 고쳤을 때 어디부터 다시 빌드하나

Dockerfile의 단계가 위에서 아래로 쌓입니다. 무엇이 바뀌었는지와 단계의 순서를 고르면, 캐시에서 다시 쓰는 단계와 다시 하는 단계가 나뉩니다.

단계의 순서

무엇이 바뀌었나

단계마다의 시간은 노트북 1교시의 가정과 같습니다(pip install 300초 등).

서비스 넷과 띄우는 순서

서비스를 누르면 compose.yaml에 적힌 내용이 오른쪽에 나옵니다. ‘띄우기’를 누르면 모델을 올리는 동안의 막대가 차고, 셋이 건강해진 뒤에 api가 시작합니다.

서비스

준비에 걸리는 시간은 설명용으로 줄인 값입니다.

숫자의 형식을 줄이고, 여러 개를 한 번에

계산 형식을 바꾸면 메모리가, 배치 크기를 바꾸면 초당 처리량이 움직입니다. 위쪽에서는 소리 조각이 배치 크기만큼씩 GPU로 들어갑니다.

장치

계산 형식

막대는 방향을 보여 주는 설명용 모형입니다. 실제 값은 노트북 2교시의 표로 확인하세요.

자리가 차거나 시간이 다 되면 출발

요청이 왼쪽에서 도착해 줄을 섭니다. 묶음이 max_batch개가 되거나 첫 요청이 max_wait만큼 기다리면 GPU로 들어갑니다. 요청이 오는 빠르기를 바꿔 줄이 어떻게 변하는지 보세요.

한 묶음을 계산하는 시간은 0.06초 + 요청 하나당 0.012초로 둔 설명용 모형입니다.

한 턴이 지나가는 길과 구간별 시간

소리가 api → asr → llm → tts를 지나 돌아옵니다. 아래 막대는 구간마다 쌓이는 시간이고, 빗금 친 부분은 계산이 아니라 줄 서서 기다린 시간입니다.

동시에 걸려 있는 통화

시간은 설명용 모형입니다(설정 A, 생각 시간 1초). 실제 값은 노트북 3 · 4교시의 표로 확인하세요.

지연은 무릎처럼 꺾인다

가로축은 동시 통화 수, 세로축은 지연입니다. 실선이 p95, 점선이 p50입니다. 통화 수를 늘려 곡선이 목표선을 넘는 지점을 찾고, 설정을 바꿔 무릎이 어디로 옮겨 가는지 보세요.

설정

곡선은 줄 서기 모형으로 그린 설명용입니다. 실제 곡선은 노트북 4교시에서 직접 잽니다.

GPU는 통화가 없어도 값을 낸다

자리 하나가 동시에 받을 수 있는 통화 하나입니다. 색이 찬 자리가 지금 통화 중인 자리(가동률)입니다. 값을 바꿔 통화 한 건의 원가가 어떻게 움직이는지 보세요. 숫자는 화면에서 실제로 계산합니다.
