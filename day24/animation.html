D24 MCP 연동

MCP(Model Context Protocol)가 푸는 N×M 문제, Host · Client · Server 구조, 함수가 도구 설명서로 바뀌는 과정, JSON-RPC 메시지 흐름, 여러 서버의 도구를 하나로 모으는 방법, annotations로 정하는 확인 정책, 도구 설명 속 숨은 지시, 음성 한 턴의 시간표를 직접 움직여 보는 수업 자료입니다. 탭 번호 D24-1 ~ D24-9는 노트북 · 워크시트 · 슬라이드의 🎬 번호와 같습니다. '한빛치과'와 '내 캘린더'는 가상 데이터입니다.

D24-1오늘 할 것: 떼어 내고 · 주고받고 · 꽂아 쓰기

단계를 눌러 할 일과 빈칸을 확인하고, 관련 애니메이션으로 이동하세요.

D24-2연결 코드는 몇 개 필요할까?

AI 앱 수(N)와 도구 · 시스템 수(M)를 바꿔 보세요. MCP를 끄면 앱마다 도구마다 따로 연결하고, 켜면 앱은 클라이언트 하나, 도구는 서버 하나만 만들면 됩니다.

D24-3서버를 꽂고 빼기

서버를 켜고 꺼 보세요. Host(음성 비서) 안에는 서버마다 클라이언트가 하나씩 생기고, LLM이 보는 도구 목록이 바로 바뀝니다. 비서 코드는 한 줄도 바뀌지 않습니다.

서버 (프로그램)

Host가 LLM에게 주는 도구 목록

D24-4파이썬 함수 → tools/list 결과

함수의 docstring · 타입 힌트 · Field 설명 · annotations를 바꿔 보세요. 오른쪽은 서버가 tools/list에 돌려주는 도구 설명서(JSON)입니다. 노란 부분이 방금 바뀐 곳입니다.

D24-5JSON-RPC 메시지 한 줄씩

상황을 고르고 '다음 ▶'을 누르세요. 보라 = 클라이언트(우리)가 보낸 요청, 초록 = 서버 응답, 회색 = 답장 없는 알림, 빨강 = 오류입니다. stdio에서는 한 줄 = 메시지 하나입니다.

D24-6여러 서버의 도구를 하나의 목록으로

서버를 고르고, 이름 앞 별명 붙이기를 켜고 꺼 보세요. 그다음 LLM이 부탁할 도구를 누르면, Host가 어느 서버로 tools/call을 보내는지 보입니다.

D24-7서버의 힌트 → Host의 확인 정책

도구를 고르거나 힌트 세 개를 직접 바꿔 보세요. '믿는 서버'를 끄면 Host는 힌트를 무시하고 가장 조심스럽게(모든 쓰기 = 확인) 판단합니다.

D24-8도구 설명 속 숨은 지시

도구 설명(description)은 LLM이 그대로 읽는 글입니다. 서버를 골라 설명을 읽어 보고, 점검기와 지문(hash) 비교를 켜 보세요.

D24-9음성 한 턴: 어디서 시간이 드나

도구 단계 수, LLM 한 번의 시간, MCP 왕복(같은 컴퓨터 · 원격), filler를 바꿔 보세요. 빨간 점선은 첫 소리 목표 1.2초입니다.
