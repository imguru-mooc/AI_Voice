D32 웹 클라이언트

브라우저 마이크 권한, 녹음 조각과 업로드, Web Audio 그래프와 오디오 스레드, 16 kHz로 바꾸기, 답 소리 재생 큐, 끼어들기, WebSocket과 WebRTC의 차이를 직접 움직여 보는 수업 자료입니다. 탭 번호 D32-1 ~ D32-9는 노트북 · 워크시트 · 슬라이드의 🎬 번호와 같습니다. 숫자는 설명용 시뮬레이션입니다.

D32-1오늘 할 것: 브라우저를 음성 비서의 귀와 입으로

단계를 눌러 할 일과 빈칸을 확인하고, 관련 애니메이션으로 이동하세요.

D32-2마이크 권한과 보안 컨텍스트

페이지 주소와 사용자의 선택을 고르면, getUserMedia가 어떻게 끝나는지 보여 줍니다. 브라우저는 https 또는 localhost에서만 마이크를 허락합니다.

D32-3녹음 조각과 업로드: MediaRecorder → Blob → FormData

조각 간격과 압축 정도를 바꾸고 ▶를 누르세요. 녹음기가 조각을 내놓고, 멈추면 조각을 이어 파일 하나(Blob)로 만들어 올립니다.

D32-4Web Audio 그래프: 128 샘플 블록이 20 ms 조각이 되기까지

브라우저 표본율을 고르고 ▶를 누르세요. 오디오 스레드는 128 샘플씩 워클릿을 부르고, 워클릿은 16 kHz 샘플을 320개 모을 때마다 우편함(postMessage)으로 보냅니다.

D32-516 kHz로 바꾸기: 위치 고르기 · 선형 보간 · ×32767

회색 점은 브라우저 표본, 색 점은 16 kHz로 고른 값입니다. 소리 주파수를 8 kHz 위로 올리면 16 kHz에서는 담을 수 없는 소리가 낮은 소리로 둔갑합니다(앨리어싱).

D32-6재생 큐: 시작 = max(지금 + 여유, nextTime)

답 소리 조각이 들쭉날쭉 도착합니다. '바로 재생'과 '재생 큐'를 비교하고, 도착 흔들림과 여유 시간을 바꿔 보세요.

D32-7끼어들기: speech_start가 오면 남은 소리 멈추기

비서가 답하는 도중 사용자가 말을 시작합니다. 사용자가 말을 시작하는 시각, 서버가 말 시작을 알아채는 데 걸리는 시간을 바꾸고 ▶를 누르세요.

D32-8WebSocket(TCP) vs WebRTC(UDP + Opus): 조각을 잃으면

조각 손실률과 왕복 시간(RTT)을 바꿔 보세요. TCP는 잃은 조각을 다시 받을 때까지 뒤 조각이 기다리고, WebRTC는 메우고 지나갑니다.

D32-9정리 퀴즈: 이 상황에서 무엇을 고칠까?

음성 위젯을 만들며 실제로 만나는 상황입니다.
